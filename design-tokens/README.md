# Protofy design tokens

One shared core, two presets that stay recognisably Protofy but read differently:

| | **Learn** — `education.css` | **Desk** — `admin.css` |
|---|---|---|
| Product | Education website | Product-selling admin app |
| Temperature | Warm paper (`#fbfaf6`) | Cool paper (`#f4f6fa`) |
| Voice | Rounded display font, larger headings | System sans, dense UI (14px) |
| Radius | 14 / 20 / 28 px | 8 / 12 / 16 px |
| Controls | 44 / 52 / 56 px | 32 / 36 / 40 px |
| Highlight | Amber `#f59e0b` | None — indigo + cyan only |
| Signature | Dark "night" bands, soft shadows | Dark sidebar, tables, status colours, charts |
| Accent use | Cyan as the friendly accent | Cyan as the "live/data" accent |

Shared DNA: navy ink, cyan → indigo, system font stacks (no CDN), 4 px spacing rhythm, 2 px focus ring, light/dark built on the same `.dark` class.

## Files

- `education.css` — Tailwind CSS v4 `@theme` + dark overrides for the education site.
- `admin.css` — same for the admin app, plus sidebar, table, order-status, commerce, and chart tokens.
- `protofy.tokens.json` — the same values as plain JSON for Figma or other tooling. The CSS files are the implementation; this mirrors them.

## Quick start (Tailwind v4)

1. Copy `education.css` or `admin.css` into the project as `src/styles/theme.css`.
2. Import it once in the root layout: `import "../styles/theme.css";`
3. Toggle `.dark` on `<html>` and persist it (same snippet the marketing site uses).
4. Build with the semantic utilities.

```html
<a class="inline-flex h-control items-center rounded-control bg-action px-5 text-action-fg hover:bg-action-hover">
    Enroll
</a>

<div class="rounded-card border border-line bg-surface p-6 shadow-card">
    <p class="text-ink-soft">...</p>
</div>
```

## Dark mode

Both presets use the same class-based variant:

```css
@custom-variant dark (&:where(.dark, .dark *));
```

- `.dark` flips surfaces, text, actions, status colours, and shadows.
- The admin sidebar is **dark in both themes** by design (`--color-sidebar` does not flip).
- Learn ships an optional `.night` class that pins a dark band (hero, CTA) inside a light page.

## Choosing between them

- Use **Learn** for anything student-facing: marketing, course catalog, lesson pages, dashboards for learners. Prioritise warmth, larger targets, and the rounded display face.
- Use **Desk** for anything operator-facing: product CRUD, orders, inventory, pricing, analytics. Prioritise density, tabular numbers, and status legibility.
- Do not mix radii, control heights, or the education highlight into the admin app. The two presets share colours so the products feel related, not identical.

## Accessibility guardrails

- `ink` on `canvas`, `ink-soft` on `canvas`, and `action-fg` on `action` are chosen to clear WCAG AA in both themes.
- `accent` (cyan) and `highlight` (amber) are **accents**, not body-text colours on light surfaces. Use `link` for text links.
- Keep the 2 px focus ring and never remove it without a replacement.
- `prefers-reduced-motion` is handled in the base layer; keep transforms behind `motion-safe:`.
- Admin tables and metrics use `font-variant-numeric: tabular-nums` globally; keep it for anything that aligns in columns.

## Versioning

Bump `$version` in `protofy.tokens.json` and note the change here whenever a value changes. Both CSS files and the JSON should stay in sync.
